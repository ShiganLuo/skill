# 饮食照片触发任务

## When to Use

- 用户在对话（飞书/Telegram/任意平台）中**上传了一张食物、餐食、外卖、做饭照片**，无论有没有配文字
- 用户明确说"记录这顿""算下热量""归档这张"且附了图
- **按需饮食咨询**：用户主动问"等下吃什么/有什么建议/今天还能吃吗/帮我看看今天吃得怎么样"——读文档中**当天**的餐食条目汇总已摄入（总 kcal、宏量），结合剩余热量空间给 2-4 条具体建议（菜品+份量+大致 kcal），**只在对话里回答：不写入文档、不主动推送**（每日建议模块已按用户要求删除）
- **不适用**：非食物图片（风景、文档、截图）→ 不归档不记录，正常对话

当触发时自动执行以下四步（用户无需再说任何指令）。

## 1. 视觉分析（用你自己的视觉能力直接看图，不调脚本）

- 列出食物清单，每项给目测分量（几何参照：饭碗、托盘格、筷子）
- 总热量给**低/中/高三档区间，中档作为记录值**
- 估算宏量：蛋白 g / 脂肪 g / 碳水 g（与总热量按 4/9/4 kcal/g 自洽）
- 记下一句话备注（主要不确定项，如"红烧肉肥瘦比、食堂用油量"）

## 2. 压缩并归档图片

- **源路径**：消息上下文里 `[Image attached at: <path>]` 给出的真实路径，不要自己猜
- **目标目录**：`/home/<USER>/Work/<USER>/Privacy/diet/`
- **文件名规范**：`YYYYMMDDHHmm.<ext>`（12 位时间戳，与旧 `diet_calorie_watch.py` 的 `NAME_RE` 兼容）
  - **时间戳三级优先：EXIF 拍摄时间 > 用户口述 > 文件 mtime**（用户已定：EXIF 最高）
    - 有 EXIF → **一律用 EXIF**，即使用户口述了别的时刻也不覆盖
    - EXIF 缺失（截图、被社交软件压缩过的图）且用户口述了时间 → 用口述兜底：口述只有时刻（"早上十点"）则日期取照片当天，未给分钟按 `00`
    - 两者都没有 → 文件 mtime
  - 扩展名保持小写（压缩输出统一 jpg）
  - 目标已存在同名 → 追加 `_1`、`_2`…（如 `202610101707_1.jpg`）
- **压缩规范（节省存储，能看清楚即可）**：
  - **先读 EXIF 拍摄时间，再压缩**——压缩会剥离 EXIF（拍摄时间已编码进文件名，顺带剥掉 GPS，隐私加分）
  - 最长边 ≤ **1600px**（PIL `LANCZOS`），JPEG **quality=85**，`optimize=True, progressive=True`，RGB
  - 实测基准：4096×3072/3.3MB → 1600×1200/约 224KB（**6.5%**），食物细节与托盘文字仍清晰
  - **截图/长图（短边 ≤1600px）不缩尺寸、只重编码 q85**——文字图缩尺寸就糊；实测 1080×6374 菜单截图 1456KB→633KB 仍清晰。照片（两边均 >1600）才缩到 1600
  - 先写 `*.tmp` → PIL `verify()` 校验通过 → `os.replace` 到目标 → **最后才删源文件**
  - 源图已 ≤1600px 且 <150KB → 直接移动，不重复压缩

## 3. 追加记录到减肥计划

目标：`/home/<USER>/Work/<USER>/work/笔记/Schedule/长期计划/减肥计划.md`

格式**严格**如下（与 `~/.hermes/scripts/diet_calorie_watch.py` 的 `fmt_entry` 一致，保证两条链路格式统一）：

```markdown
### YYYY-MM-DD HH:MM（YYYYMMDDHHmm）
- 食物: 米饭约300g、红烧肉约90g、辣椒炒蛋
- 热量: 约1030 kcal（895-1170）
- 宏量: 蛋白45g / 脂肪48g / 碳水105g
- 备注: 食堂套餐；红烧肉肥瘦比与用油量是主要不确定项
```

规则：

1. 文件为空/不存在 → 先写标题 `# 减肥计划 · 饮食热量记录\n\n` 再写条目
2. **幂等**：写入前检查 12 位时间戳 fid 是否已在 md 中，已存在则跳过写入
3. 时间戳从文件名解析（`strptime(fid, "%Y%m%d%H%M")`），标题行用它的 `YYYY-MM-DD HH:MM`
4. **按图片时间升序排列（早→晚）**：新条目**不是无脑追加到末尾**，而是按解析出的时间插入到正确位置——比已有条目早就插它前面，晚就放最后；标题行永远在最顶；写完后所有 `###` 条目时间必须严格递增
   - 文档只有标题 + 餐食条目两种内容，**不设"每日建议"节**（用户已删除该模块）——md 只存热量数据，建议只在对话里给

## 4. 回复用户

简短三行内：热量结论（中档+区间）、归档后的完整路径、已记录确认。
宏量和备注可省略（已在 md 里）。

## 坑

- 图片来自各平台的 `~/.hermes/cache/images/`，是临时缓存——**必须移动走**，否则只存在于对话里
- 飞书图片带 EXIF（Xiaomi 15 Ultra 有 `DateTime`），拍摄时间可能比上传时间早几小时，**以拍摄时间为准**
- 不要往 md 里追加日志性文字（如"已归档"），md 只放热量记录条目
