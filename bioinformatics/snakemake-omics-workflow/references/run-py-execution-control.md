# run.py Execution Control: --forcerun, --touch, --rerun-triggers

## Problem solved

Omics .smk rules generate .sh scripts (in `run:` blocks) that contain bare
commands (python/Rscript/cutadapt) without environment wrapping. These scripts
cannot be executed standalone -- they depend on snakemake's `--sdm apptainer`
or `--use-conda` to provide the runtime environment at the rule level.

## run.py CLI parameters (execution control)

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `--dry-run` | flag | false | Snakemake dry-run |
| `--touch` | flag | false | Touch output files without re-running |
| `--forcerun` | `str nargs='+'` | None | Force re-run specific rules |
| `--unlock` | flag | false | Unlock snakemake working directory |
| `--rerun-trigger` | `str nargs='+'` | all 5 | Snakemake rerun-triggers |
| `--no-schema-validate` | flag | false | Disable schema-based type casting |
| `--snakemake-args` | REMAINDER | [] | Raw args forwarded to snakemake |

### --touch

Updates output file timestamps without re-running rules. Useful when outputs
exist but snakemake's metadata is stale/incomplete.

```bash
python run.py ... --touch          # touch all outputs
python run.py ... --touch --dry-run  # WARNING: --dry-run prevents --touch
```

**Conflict with --dry-run:** `--touch` + `--dry-run` is detected in `__main__`,
warns, and sets `args.touch = False`. Cannot meaningfully combine because
--dry-run prevents all file operations.

### --rerun-triggers

Controls WHEN snakemake re-runs completed jobs. Default: all 5 triggers.

```bash
python run.py ... --rerun-triggers input   # only check input file changes
python run.py ... --rerun-triggers mtime   # only check modification times
```

**Common misconception:** `--rerun-triggers input` does NOT mean "skip if
output exists". It means "only check input file changes for re-run decisions".
If output files don't exist, snakemake MUST run the rule regardless of trigger.

Snakemake rerun-triggers: `code`, `input`, `mtime`, `params`, `software-env`.

### --no-schema-validate

Disables `SchemaValidator.cast_extra_args()` for extra_args. See
`schema-validator.md` for the full validation pipeline.

## --forcerun parameter

Added to `run.py` `parse_args()`:
```python
parser.add_argument('--forcerun', type=str, nargs='+', default=None,
    help='force re-run specific jobs, e.g. --forcerun trimming_Paired:sample_id=S1')
```

In `build_snakemake_cmd()`, `--until` and `--forcerun` are BOTH passed with
the same targets (snakemake uses `--until` to cap the DAG and `--forcerun`
to force re-run within it):
```python
if forcerun:
    cmd.append("--until")
    cmd.extend(forcerun)
    cmd.append("--forcerun")
    cmd.extend(forcerun)
```

### Auto-prefix with workflow name

In `execute_workflows()`, rule names are auto-prefixed with `{wf_name}_`:

```python
# Input: --forcerun scanpy_qc
# Output: --forcerun scRNAseq_scanpy_qc
```

Exceptions (no prefix added):
- `all` — special snakemake target
- Already prefixed: `scRNAseq_scanpy_qc` → stays as-is
- **File paths** (contains `/`): passed through as-is

### File path detection

If a `--forcerun` target contains `/`, it's treated as a file path and passed
to snakemake without workflow-name prefix:

```bash
# Rule name → auto-prefixed
--forcerun scanpy_qc → scRNAseq_scanpy_qc

# File path → passed through
--forcerun /path/to/output.bam → /path/to/output.bam

# Already prefixed → no change
--forcerun scRNAseq_scanpy_qc → scRNAseq_scanpy_qc
```

### Usage

```bash
# Single rule
python run.py ... --forcerun scanpy_qc

# Multiple rules
python run.py ... --forcerun scanpy_qc scanpy_merge

# File path target
python run.py ... --forcerun /path/to/output.h5ad

# With wildcard (snakemake version-dependent!)
python run.py ... --forcerun trimming_Paired:sample_id=S1
```

## Snakemake wildcard syntax in --forcerun

**Pitfall:** Not all snakemake versions support `RULE:WILDCARD=VALUE` syntax
for `--forcerun`/`--until`. Some versions treat `RULE:WILDCARD=VALUE` as a
file path, causing `MissingRuleException` or `AttributeError: 'str' object
has no attribute 'is_storage'`.

If wildcard syntax fails, use rule names without wildcards:
```bash
# Instead of --forcerun scanpy_qc:counter=scTE
# Use --forcerun scanpy_qc (re-runs for ALL counters)
```

To re-run only a specific counter/wildcard value, target the output file path:
```bash
--forcerun /path/to/output/{sample}_{counter}_qc.h5ad
```

## How outfiles and --forcerun interact

- `outfiles` (generated by `run<Workflow>()` in run.py) defines `rule all`'s
  input, which determines the DAG boundary.
- `--forcerun` forces re-execution of matching jobs **within the DAG** plus
  their upstream dependencies. It does NOT run downstream rules.
- If a target's output is not in the `outfiles` dependency chain, it's not in
  the DAG, and `--forcerun` won't trigger it.

## Snakemake target syntax reference

| Mechanism | CLI | Semantics |
|-----------|-----|-----------|
| Positional target | `snakemake ... rule:wildcard=val` | Run target + upstream + downstream |
| `--forcerun` | `snakemake ... --forcerun rule` | Force re-run target + upstream, NOT downstream |
| `--until` | `snakemake ... --until rule` | Run DAG up to rule, skip downstream |
| `--touch` | `snakemake ... --touch` | Update output timestamps, don't re-run |
| `--rerun-triggers` | `snakemake ... --rerun-triggers input` | Only check specified triggers |
