# Python Argparse Bugs and Pitfalls

## Common Bug: `not 'string'` Always Evaluates to False

In Python, `not 'string'` evaluates to `False` for any non-empty string. This is a common bug in argparse `required` logic:

```python
# BROKEN: not '--species' always evaluates to False
required = (not '--species' or '-s' in sys.argv) or ('-t' in sys.argv)
# This is equivalent to: (False or '-s' in sys.argv) or ('-t' in sys.argv)

# CORRECT: should be
required = not ('--species' in sys.argv or '-s' in sys.argv)
```

### Real Example — mimseq

The `--trnaout` parameter is marked as "optional" in help text but is actually required due to this bug:

```python
# In mimseq source code:
parser.add_argument('-o', '--trnaout', 
    metavar='tRNA out file', 
    required=(not '--species' or '-s' in sys.argv) or ('-t' in sys.argv),
    dest='trnaout', 
    help='tRNA.out file generated by tRNAscan-SE')
```

**Diagnosis**: When a tool says a parameter is optional but fails when you omit it, check the source code for this pattern.

**Fix**: Always provide the parameter, even if help text says it's optional.

## Other Common argparse Bugs

### Bug 1: `default=None` with `required=True`

```python
# BROKEN: default=None but required=True
parser.add_argument('--umi-length', default=None, required=True, type=int)
```

**Help text shows**: `--umi-length UMI_LENGTH (default: None)`
**Actual behavior**: Parameter is required, cannot be omitted or set to None

### Bug 2: Missing `action="store_true"` for boolean flags

```python
# BROKEN: Missing action
parser.add_argument('--verbose', help='Enable verbose output')

# CORRECT: Should be
parser.add_argument('--verbose', action='store_true', help='Enable verbose output')
```

## Testing Checklist

Before writing Snakemake rules for a new tool:

1. **Run `tool --help`** to see parameter documentation
2. **Test with parameters omitted** to verify which are truly optional
3. **Test with `None` values** to verify default behavior
4. **Check tool source code** if behavior doesn't match documentation

## Workarounds

### For `not 'string'` Bug
The parameter IS required. Provide it in your Snakemake rule:
```python
cmd = ["tool", "--required-param", value, "--actually-required-param", value]
```

### For `default=None` with `required=True`
The parameter is required. Provide it even if you want "None":
```python
# If the parameter must be an integer, provide a dummy value
cmd = ["tool", "--umi-length", "12"]  # Use actual value, not None
```
