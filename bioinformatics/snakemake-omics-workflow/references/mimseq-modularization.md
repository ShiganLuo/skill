# mimseq modularization — pitfalls and patterns

When splitting a monolithic tool (like mimseq) into independent Snakemake modules with pickle state passing.

## Critical pitfalls

1. **Global variables reset between modules**. Monolithic tools often use module-level globals (e.g. `stkname = ''` in ssAlign.py). Each module runs in a fresh Python process, so globals are empty. Fix: set them explicitly in each wrapper before calling the tool functions:
   ```python
   import mimseq.ssAlign as ssAlign_module
   stk_files = glob.glob(os.path.join(out, "*_align.stk"))
   ssAlign_module.stkname = stk_files[0]
   ```

2. **Function imports need module prefix**. If you import `import mimseq.mmQuant as mmQuant_module`, calls must be `mmQuant_module.generateModsTable(...)`, not bare `generateModsTable(...)`.

3. **`anticodon` can be empty**. `clusterAnticodon()` returns `[]` when the cluster name doesn't match any stk record. Guard with `and anticodon` before `min(anticodon)`.

4. **`_coverage.txt` files are generated by one module and consumed by another**. In mimseq, `bamMods_mp` (mods) writes `_coverage.txt` and `getCoverage` (coverage) reads+deletes them. If mods runs with `remap=True`, the files ARE still written (line 341 is unconditional). But getCoverage deletes them after reading, so a failed coverage run leaves them gone. Re-run mods to regenerate.

5. **`--control-cond` empty string breaks argparse**. When `control_cond=""`, argparse treats the next flag as its value. Fix: only add `--control-cond` when non-empty, and make it `default=""` (not `required=True`).

6. **CCA/modPlot data only generated with `remap=False`**. When mods runs with `remap=True`, CCA output and mod tables are NOT generated. Guard downstream R scripts with file-existence checks.

7. **`os.path.exists()` for optional files**. gsnap may not generate `.unpaired_transloc` files. Always check existence before operating.

## Per-sample directory structure

When tools write per-sample files flat into `out_dir` (e.g. `out_dir + bam_name + suffix`), refactor to use per-sample subdirectories:

- Add `sample_dir` parameter to mapping/alignment functions (default `None` → falls back to `out_dir`)
- Create `{out_dir}/samples/{sample_name}/` before processing
- Write BAM/FASTQ outputs to `sample_dir`, shared files (logs, stats) to `out_dir`
- `_coverage.txt` and similar per-sample intermediates should follow the BAM path (`os.path.dirname(inputs)`)
- Update ALL references: `out_dir + file.name` → `sample_dir + file.name` in the entire function — easy to miss nomapping/mult/transloc branches
- `_predictedModstemp.csv` uses `inputs + suffix` (relative to BAM), so it follows automatically

## Snakemake .smk bash script patterns

Every `run:` block that generates a bash script must include:
```python
f.write("#!/bin/bash\n")
f.write("export PATH=/path/to/conda/env/bin:$PATH\n")
f.write("/path/to/conda/env/bin/python script.py --args\n")
```
Common mistake: bare `"python"` instead of full conda python path. The PATH export ensures samtools/bedtools/gsnap are available in the worker.

## mimseq module dependency chain

```
prepare_sample_data → tRNAtools → align → clusters → mods → coverage → deseq → result
```

State transfer via pickle files in `{out}/state/`. Each module loads states from upstream modules.
